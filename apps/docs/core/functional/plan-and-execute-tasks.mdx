Open a project and choose **Tasks**. To change how the same work is displayed, open **Display** at the top right and pick a layout: **Board**, **List**, **Calendar**, or **Gantt**.

Most actions have a keyboard shortcut: for example **C** creates a task, **G** then **I** opens your inbox, and **⌘B** switches between Board and List. Press **?** (or **⌘/**, **Ctrl+/** on Windows and Linux) anywhere to see and search every shortcut.

## Add a task

Choose **New** and then **New task**. On the board, the **+** control in each column opens the same menu and keeps that column selected. Home, project views, the backlog, releases, and Feature task sections offer **New task**, **New feature**, and **New bug** through the same creation menu. Give the item a title that describes the work, then open it to add details.

A title such as “Fix the mobile navigation” is easier to act on than “Mobile issues.” Use the description for context, links, and a checklist of smaller steps.

### Track a bug

Choose **New → New bug**, or choose **New bug** in the command menu. You can also select **Bug** in the creation window's **Type** selector. The **C** shortcut still starts a Task. In a Feature's task section, **New task** and **New bug** keep the quick inline title entry.

Bugs have the same properties, workflow, numbering, permissions, and actions as Tasks. A bug icon identifies them on cards, rows, calendars, Gantt, My Work, public boards, and search. A Bug can belong to a Feature and a Release. Bugs count as tasks in feature progress, release totals, and release progress charts.

To change an existing item's classification, open **Type** in its properties or use its card or row's conversion menu. Converting between Task and Bug keeps the same item, including its feature, release, comments, attachments, labels, dates, and history. Converting either to Feature takes it out of its parent feature and keeps its release. A Feature can become a Task or Bug only after all its children have been removed.

## Move work on the board

Use [Feature milestones](/core/functional/milestones) to break a Feature into smaller stages. Select a milestone in the Feature overview to filter its Tasks list, or assign it from the Task/Bug's properties after selecting its Feature.

Drag a task to another column when its status changes. You can also change its status inside the task.

## Find and filter work

Use the search icon, or press ⌘F (Ctrl+F on Windows and Linux), to find tasks by title, description, or task number.

Use **Filter** to narrow the view by type, status, assignee, priority, labels, release, due date, or custom fields. Hover a property to pick its values, or type in **Add filter…** to search every value at once. Each filter appears as a chip above the tasks:

- Click the operator, such as **is**, to switch it to **is not** and hide matching tasks instead.
- Click the values to change them.
- Choose **×** to remove the filter, or **Clear all** to remove every filter.

Filters are saved for each project and apply to every layout. The count next to **Tasks** shows how many tasks match. If a task seems to have disappeared, clear your filters and check the backlog before creating another one.

The **Type** filter offers Task, Bug, and Feature, with counts for each. Selecting more than one includes any selected type; other filters still apply. Use **is not** to exclude the selected types. Projects with older saved filters initially include all types. Filtering changes the visible items, while feature and release progress continue to count all their work.

Open **Display** to sort tasks and choose which details appear on cards and rows. Filled custom fields show as small chips on cards and rows; hover one to see the field name. Under **Fields**, turn off any field you don't want there. These choices are saved in your browser and only affect your view.

## Add the details people need

Open a task to edit its description and properties. Use **Open in full page** from the task panel when you want more space.

- **Assignee:** choose the person responsible for the next step. Clear it to leave the task unassigned.
- **Priority:** show what needs attention first. A task can have no priority.
- **Dates:** add start and due dates when the work has a schedule.
- **Labels:** group related work across projects. Removing a label from one task does not delete the workspace label.
- **Release:** put the task in one of the project's [releases](/core/functional/releases), or choose **No release**. In an open task, **Shift+C** changes it.
- **Comments:** ask questions and record decisions where everyone following the task can find them.

Use the attachment button, paste, or drag a file into the editor to add supporting material. Images appear inline; other files appear as attachments. On self-hosted instances, an operator must [configure file storage](/core/installation/object-storage-and-image-uploads) first.

## Group work into features

A feature is a task that groups other tasks, like an epic. Use one for a larger piece of work that several tasks deliver together, such as “New onboarding flow.” A feature stays on the board as a card, with its own status, assignee, dates, and comments.

Use checkboxes in the description for a simple checklist. Use a feature when each piece needs its own owner or progress tracking.

### Make a feature

To create a new feature, choose **New → New feature**, or **New feature** in the command menu. In the creation window you can also switch **Type** to **Feature** before you create it.

To turn an existing task into a feature, open it, select **Type** in its properties (it shows **Task**), and choose **Convert to feature**. You can also right-click its card on the board, or its row in List, and choose **Convert to feature**. The card then shows a **Feature** badge.

To turn a feature back into a task or bug, choose **Convert to task** or **Convert to bug** in the same places. A feature that still has Tasks or Bugs can't become a leaf item. Take its tasks out of it first.

### Add tasks to a feature

- When you create a task, select **Feature** and pick one of the project's features. Type a name that isn't there yet and choose **Create feature** to make a new one. When you create the task, Kaneo creates the feature first and then the task in it. If the task can't be created, the feature stays and is still chosen when you try again. The list shows the features of the task's project, so choose the project first.
- Open the feature. In its **Tasks** section, open **+**, choose **New task** or **New bug**, enter a title, and choose **Add**. The new item is created inside the feature. **New feature** creates a separate Feature in the same project and release.
- Open a task, select its **Feature** property, and pick one of the project's features.

A task belongs to one feature at most, and only to a feature in its own project. A feature can't belong to another feature, so it has no **Feature** property, and turning a task into a feature takes it out of its feature.

To take a task out of its feature, do one of these:

- Pick **No feature** in the task's **Feature** property.
- Choose **Remove from feature** (**×**) next to the feature's name at the top of the task.
- Right-click the task's card or row and choose **Remove from feature**.
- In the feature's **Tasks** section, hover the task and choose **Remove from feature** (**×**).

The task itself stays. To move it to another feature, pick that feature in its **Feature** property.

### Follow a feature's progress

A feature's card shows how many of its Tasks and Bugs are done, such as **2/5**. Hover or select the count to list the tasks, and select one to open it. Each task in a feature shows the feature's name on its card and in List. Select the name to open the feature. In an open task, the **Feature** link at the top takes you to its feature. On the Gantt chart, features have [their own bar style](/core/functional/calendar-and-gantt#features), and you can [group tasks by feature](/core/functional/calendar-and-gantt#group-by-feature).

The task's activity records when you add it to a feature, take it out, or change its feature, and when its type changes. It also records when the task leaves its feature because it moved to another project or its feature was deleted. Creating a task inside a feature records only its creation.

### What happens to the tasks

- **Deleting a feature** keeps its tasks. They just leave the feature.
- **Moving a task to another project** takes it out of its feature and its release.
- **Moving a feature to another project** works only when it has no tasks. Take its tasks out first.
- **Duplicating a task** puts the copy in the same feature and release. A copy of a feature is a new feature in the same release, without tasks.

### Features and releases

When you put a feature in a [release](/core/functional/releases), its tasks that were in the feature's previous release move with it. A task you create in the feature starts in its release, and a task without a release takes the feature's release when it joins. A task you put in another release on its own stays there, and taking a task out of its feature keeps its release. See [How tasks follow their feature](/core/functional/releases#how-tasks-follow-their-feature) for examples.

### Subtasks from earlier versions

Earlier versions of Kaneo had subtasks. When your instance is upgraded, they are converted automatically:

- A top-level task that had subtasks becomes a feature, and its subtasks become its tasks.
- Deeper levels are flattened. A subtask of a subtask becomes a task of the top feature too, and its link to the subtask above it is kept as a **Related** relation.
- Other links that don't fit, such as a second parent or a link to a task in another project, are also kept as **Related** relations.

No task is deleted. Operators can find the details in [Upgrade Kaneo](/core/operations/upgrades#subtasks-become-features).

## Link related work

Open **Relations** and use the add button to find another task. Choose **Related** for a connection or **Blocks** when the current task must be resolved before the other one. The other task shows the inverse **blocked by** relationship.

Use **Remove relation** to unlink the tasks without deleting either task.

## Fill in custom fields

If your project defines extra fields, they appear under **Fields** in the task's **Properties** sidebar. In the side panel and when you create a task, they show as chips below status and priority. Click a field to set its value; a checkbox field toggles in place. Fields can hold text, numbers, dates, one or several dropdown choices, or a checkbox. A project manager defines the fields in [Custom fields settings](/core/functional/configure-workflows#set-up-custom-fields).

Required fields always keep a value, so they have no **Clear** option. If one is still empty when you create a task, Kaneo highlights it and tells you how many are missing.

## Delete a task

Use **Delete Task** only when you want to remove the task, rather than mark it done. Check the confirmation before proceeding. If deletion or assignment is unavailable, your workspace role may not permit it.

For work you want to keep but are not ready to start, use the [backlog](/core/functional/backlog-planning).
