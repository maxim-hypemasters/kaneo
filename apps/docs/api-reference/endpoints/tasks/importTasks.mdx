---
title: "Import tasks"
openapi: "POST /task/import/{projectId}"
---

An imported item's optional `type` accepts `task`, `bug`, or `feature`. Omit it
for older files to create a Task. Importing a Bug uses the same workflow and
permissions as importing a Task; labels do not determine the type.

Version 3 documents preserve Feature and milestone hierarchy through portable source keys, mapped to newly generated IDs. The document imports atomically; malformed references fail without partial work. Importing hierarchy requires `task:update` as well as `task:create`. Legacy documents retain individual task outcomes and default to no milestone.

Version 2/3 label definitions and attachments also require `label:create` and `label:update`, following the normal label permission rules.

Version 3 preserves release definitions, milestone lead/priority/release and informational derived status, Feature archive state, and immutable planning-history snapshots. Older hierarchy files remain accepted; former Feature planning values become history rather than active fields. Imported releases require `project:update`, and assigning a nonnull milestone lead requires `task:assign`.

Milestone status and dates are read-only, derived from linked nonarchived Tasks/Bugs after import. Legacy manual milestone status and dates remain accepted in older files but never override the derived values.
